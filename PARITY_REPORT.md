- IPD-KIR alleles (full-length precursors): worst case `typicality` on KIR3DL2*0010101
- deposited structural KIR chains: worst case `typicality` on 8tmu_C

`score`, the per-gene log-odds and the domain scores are **bit-identical**. Viterbi is max-plus, so the model score has no summation to reorder; the null score does, and `src/hmm.rs` reproduces both of the reference's summation orders separately -- numpy's blocked pairwise sum for `log_odds_score`, and the sequential accumulation of `_viterbi_core_batch` for the scan and the domain sweep. `confidence` and `gene_confidence` follow from those, so they are bit-identical too.

`typicality` is the one value that is not bit-exact: it needs a normal CDF, scipy's `ndtr` is a Cephes rational approximation, and the plugin computes `erfc` via the incomplete gamma function instead. No decision reads it -- `is_kir`, the gene call, the tie set and the architecture are all settled before it is computed -- and it saturates on structural input by design (`histo_kir_hmm` invariant 12), so it must not be thresholded in either implementation.

## Throughput

A column of 200 structural KIR chains (median length 197 residues), best of 3 runs, with the reference's numba JIT warmed first so this is steady-state throughput rather than compilation:

| | wall time | per sequence |
| --- | --- | --- |
| plugin (one Polars pass) | 0.87 s | 4.4 ms |
| reference (Python loop over `type_chain`) | 6.43 s | 32.2 ms |

**7.4x** on this shape.

The win is not "compiled beats interpreted" -- the reference's Viterbi core is already numba-JIT'd machine code. It is that the plugin runs without the GIL and fans the work out across cores: 15 gene models per sequence, and hundreds of window placements per domain segmentation.
